---
code: E0322
name: EmptyMerges
title: `check` of a value that can be `Empty`
spec: 8.4
---

`check` (`?`) keeps a value's successes and turns its errors into
`Empty`. When the successes already contain `Empty`, as in an
`Option[T] | NotFound`, success and failure would merge, so this is
refused.

## Rationale

After the merge no one could tell a missing value from a failure.
Handle the errors with `case` or `let … else`, or use `expect` (`!!`) if
an error is a bug.

## Failing

```crag
type NotFound(..Error)

fn nickname(id: Int) -> Option[Str] | NotFound {
  if id == 0 { return NotFound() }
  Empty
}

fn greeting(id: Int) -> Str {
  case ? nickname(id) {
    n: Str -> "Hello, {n}"
    _ -> "Hello"
  }
}
```

## Fixed

```crag
type NotFound(..Error)

fn nickname(id: Int) -> Option[Str] | NotFound {
  if id == 0 { return NotFound() }
  Empty
}

fn greeting(id: Int) -> Str {
  case nickname(id) {
    n: Str -> "Hello, {n}"
    _ -> "Hello"
  }
}
```
