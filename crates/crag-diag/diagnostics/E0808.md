---
code: E0808
name: MixedStores
title: An `atomic` block over `dur` bindings of two stores
spec: 21.6
---

One `atomic` block may touch `ref` and `dur` bindings together, but its
`dur` bindings must come from one store: a storage transaction never
spans two stores (§21.6). When the `dur` bindings an `atomic` block
touches visibly come from two different store bindings, the block is
refused. Bindings that arrive as `Dur[T]` parameters are checked at
run time instead, where a violation makes the commit return
`MixedStores`.

## Rationale

A commit is one storage transaction, atomic on disk. Two stores are two
files, and nothing makes two file writes atomic together; a block that
needs both cannot be given the atomicity it claims.

## Failing

```crag
type StoreA
type StoreB
fn slot(s: StoreA, v: Slot[Int] | StoreError) -> Slot[Int] | StoreError { v }
fn slot(s: StoreB, v: Slot[Int] | StoreError) -> Slot[Int] | StoreError { v }

fn f(a: StoreA, b: StoreB, va: Slot[Int] | StoreError, vb: Slot[Int] | StoreError) -> () | StoreError {
  dur x: Int = a.slot(va) else { e -> return e }
  dur y: Int = b.slot(vb) else { e -> return e }
  atomic {
    x.update(_ + 1)
    y.update(_ + 1)
  }
}
```

## Fixed

```crag
type StoreA
type StoreB
fn slot(s: StoreA, v: Slot[Int] | StoreError) -> Slot[Int] | StoreError { v }
fn slot(s: StoreB, v: Slot[Int] | StoreError) -> Slot[Int] | StoreError { v }

fn f(a: StoreA, b: StoreB, va: Slot[Int] | StoreError, vb: Slot[Int] | StoreError) -> () | StoreError {
  dur x: Int = a.slot(va) else { e -> return e }
  dur y: Int = b.slot(vb) else { e -> return e }
  atomic { x.update(_ + 1) }
  atomic { y.update(_ + 1) }
}
```
